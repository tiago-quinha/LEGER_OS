# 01.07 - Portfolio & Market Data Engine SOP

## Executive Overview
The **LEGER_OS Portfolio & Asset Management System** enables users to track multi-asset holdings (Stocks, ETFs, Cryptocurrencies, Cash Savings, Commodities, and Custom Positions) alongside their liquid bank account balances. It calculates true total net worth, unrealized PnL returns, asset class allocations, and historical daily valuation snapshots with live market search and automated price sync.

---

## 1. Database Schema & RLS Security Invariants

The system operates on two dedicated PostgreSQL tables managed via Supabase PostgREST:

### `portfolio_assets` Table
- `id`: UUID PRIMARY KEY DEFAULT `gen_random_uuid()`
- `user_id`: UUID REFERENCES `auth.users(id)` ON DELETE CASCADE
- `asset_name`: TEXT NOT NULL
- `symbol`: TEXT (e.g. `AAPL`, `VWCE.DE`, `BTC`, `ETH`, `GOLD`)
- `asset_type`: TEXT CHECK IN (`stock_etf`, `crypto`, `cash_equivalent`, `commodity`, `other`)
- `quantity`: NUMERIC(18, 8) NOT NULL DEFAULT 0
- `buy_price`: NUMERIC(14, 2) NOT NULL DEFAULT 0 (Cost basis per unit)
- `current_price`: NUMERIC(14, 2) NOT NULL DEFAULT 0 (Current market unit price)
- `currency`: TEXT NOT NULL DEFAULT 'EUR'
- `institution`: TEXT (Broker/Wallet name, e.g. `Trading 212`, `Degiro`, `Kraken`, `Santander`)
- `notes`: TEXT
- `metadata`: JSONB DEFAULT `'{}'::jsonb` (Stores `change24h`, exchange info, custom icons)

### `portfolio_snapshots` Table
- `id`: UUID PRIMARY KEY DEFAULT `gen_random_uuid()`
- `user_id`: UUID REFERENCES `auth.users(id)` ON DELETE CASCADE
- `snapshot_date`: DATE NOT NULL DEFAULT CURRENT_DATE
- `total_net_worth`: NUMERIC(14, 2) NOT NULL
- `liquid_cash`: NUMERIC(14, 2) NOT NULL
- `invested_capital`: NUMERIC(14, 2) NOT NULL
- `total_gain_loss`: NUMERIC(14, 2) NOT NULL
- `asset_breakdown`: JSONB NOT NULL DEFAULT `'{}'::jsonb`
- `UNIQUE(user_id, snapshot_date)`

### Security Policy (RLS)
Both tables MUST enforce strict Row Level Security policies (`auth.uid() = user_id`). Users can only query, insert, update, or delete their own assets.

### PostgREST Cache Invariant
All migration scripts and schema changes MUST end with:
```sql
NOTIFY pgrst, 'reload schema';
```

## 2. Live Multi-Asset Search Architecture (`/api/portfolio/search`)

Instead of hardcoded asset lists, the system exposes a live search endpoint querying global market databases in real time:

1. **Global Equities, ETFs, Indices & Commodities (Yahoo Finance)**:
   - Endpoint: `https://query2.finance.yahoo.com/v1/finance/search?q={query}&quotesCount=8&newsCount=0`
   - Covers: US & international stocks (`AAPL`, `PLTR`, `ARM`), European ETFs (`VWCE.DE`, `SXR8.DE`, `IWDA.AS`), commodities (`GC=F`, `CL=F`), and Forex pairs.
   - Maps `quoteType` to LEGER_OS asset categories (`EQUITY` -> `stock_etf`, `ETF` -> `stock_etf`, `COMMODITY` -> `commodity`, `CURRENCY` -> `cash_equivalent`).

2. **Cryptocurrencies (CoinGecko Search)**:
   - Endpoint: `https://api.coingecko.com/api/v3/search?query={query}`
   - Covers: 10,000+ crypto tokens, returning official coin ID, name, ticker symbol, market cap rank, and token logo thumbnails.

3. **Debounced UI Search (500ms Delay)**:
   - The search input in `PortfolioView.tsx` enforces a **500ms debounce** timer.
   - Prevents letter-by-letter request spam and ensures queries only dispatch once the user finishes typing.
   - While searching, animated skeleton loaders maintain layout stability.

4. **Instant 1-Click Fill & Quote Sync**:
   - Selecting a search result immediately populates the asset form and dispatches a background quote fetch (`/v8/finance/chart` or `/api/v3/simple/price`) to auto-fill the current market unit price.

## 3. Dynamic Live Preset Pricing (`GET /api/portfolio/market-data`)

1. **Real Market Quotes on Default Cards**:
   - Default quick-pick shortcut cards (Bitcoin, Ethereum, Apple, Nvidia, S&P 500, etc.) no longer rely on static estimates.
   - On page load or opening the **Add Position** drawer, `GET /api/portfolio/market-data` fetches live batch quotes for all preset tickers in a single server call.

2. **Server-Side In-Memory Cache (10-15 min TTL)**:
   - Market quotes and search queries are stored in an in-memory `Map` with a 10 to 15-minute TTL.
   - Repeated queries across components and page navigations return in `0ms` with zero external API calls.

3. **Single-Batch Optimization (Rate-Limit Protection)**:
   - All crypto tokens are requested in a single comma-separated batch parameter (`ids=bitcoin,ethereum,solana,...`), consuming only **1 CoinGecko credit** per refresh.
   - Manual price refreshes (`POST /api/portfolio/market-data`) enforce a **30-second cooldown** per user (`USER_THROTTLE_MS = 30000`).

## 5. Mathematical Standards & Formulas

1. **Total Invested Capital**:
   $$\text{Invested} = \sum_{i} (\text{quantity}_i \times \text{buy\_price}_i)$$
2. **Total Portfolio Valuation**:
   $$\text{Portfolio Valuation} = \sum_{i} (\text{quantity}_i \times \text{current\_price}_i)$$
3. **Unrealized Gain / Loss (PnL)**:
   $$\text{Total PnL} = \text{Portfolio Valuation} - \text{Invested}$$
   $$\text{PnL \%} = \left( \frac{\text{Total PnL}}{\text{Invested}} \right) \times 100$$
4. **True Total Net Worth**:
   $$\text{Total Net Worth} = \text{Liquid Bank Balance} + \text{Portfolio Valuation}$$

## 6. Paycheck Cycle Synchronization & Trajectory Invariants

1. **Cycle Header & Bottom Bar Alignment**:
   - The Portfolio page header strictly displays the active paycheck cycle label (e.g. `[28 JUL - PRESENT]`) with the subtitle eyebrow `<TrendingUp /> ACTIVE PAYCHECK CYCLE`.
   - The sticky `CycleMobileBar` is stationed above the bottom navigation bar (`route="/portfolio"`), supporting swipe gestures and direct cycle switches.
   - When an account has 0 transactions or paychecks, `getCycles` in `src/lib/cycles.ts` automatically generates calendar month cycles starting from Day 1 (`01 AUG - Present`) to prevent empty state crashes.

2. **Date-Accurate Acquisition Modeling**:
   - Assets only contribute to day $d$'s net worth on or after their creation/purchase date (`new Date(asset.created_at) <= dateEnd`).
   - Prior to acquisition, the curve reflects only actual bank balances. When an asset is added or increased in quantity, the graph reflects the spike specifically on that day forward, never retroactively inflating past days.

3. **Solid vs. Dashed Future Trajectory Protocol**:
   - **Past Days through Today**: Plotted as a solid line (`strokeWidth={2}`, `type="stepAfter"`) representing empirical bank cash and acquired holdings.
   - **Future Days**: Plotted as a dashed projection (`strokeDasharray="5 5"`, `strokeOpacity={0.6}`) connecting seamlessly at today's coordinate with `connectNulls={true}`.

4. **Sub-Cent Micro-Asset Precision Standard**:
   - Cryptocurrencies and penny assets (e.g. `SHIB`, `PEPE`, `DOGE`) must preserve up to 8 decimal places of precision without `toFixed(4)` truncation in market data endpoints.
   - Formatted using `formatSmartPrice` and `formatSmartQuantity` in `PortfolioView.tsx` so sub-cent values (e.g. `€0.00001234`) display clearly.

5. **Direct Live Server Hydration (Zero-Snapshot Lag)**:
   - The portfolio view receives `initialLiquidBalance` and `initialAssets` directly from the server component (`src/app/portfolio/page.tsx`), eliminating initial skeleton flicker and preventing stale snapshot dependence.
   - Today and future points on the chart compute dynamically from live React state (`assets`, `liquidBalance`), ensuring quantity changes and deletions update instantly without requiring page refreshes.

## 9. Frictionless Entry Modes & Currency FX Normalization

1. **Dual Entry Mode (`[ Price per Share | Total Invested ]`)**:
   - In `PortfolioView.tsx`, users can toggle between entering unit prices (e.g. `€180.00 / share`) or total cash spent (e.g. `€10.00 total`).
   - When entering total cash spent and fractional quantity, the engine automatically calculates `buy_price = total_spent / quantity` behind the scenes, eliminating broker ticket calculation errors.

2. **Universal Dynamic Forex Engine (`src/lib/forex.ts`)**:
   - Real-time exchange rates (`EURUSD=X`, `GBPUSD=X`, `EURGBP=X`) are fetched dynamically from Yahoo Finance with a 30-minute server cache.
   - Converts any asset quote (USD, GBP, GBX, EUR) into the user's active profile currency (`profiles.currency`).
   - Automatically normalizes live market quotes in both `GET` / `POST` `/api/portfolio/market-data` and live asset search quick-fills.

3. **15-Minute Automated Background Sync**:
   - `PortfolioView.tsx` runs an automated background sync every 15 minutes (`setInterval`) and upon window focus (`focus` event).
   - Rate-limit safe: Uses server-side in-memory caching (`15 min TTL`), consuming <0.2% of public API limits.
