# SOP - System Monetization & Design Standards

## 1. Emerald PRO Branding & Non-PRO Color Invariant
- **Emerald Green Exclusivity**: Reserve Emerald Green (`text-emerald-500`, `bg-emerald-500/10`, `border-emerald-500/30`) strictly for **PRO / Premium** features, lock badges, and upgrade cards.
- **Monochrome Non-PRO Utilities**: Non-PRO security/privacy indicators (e.g., Privacy Safe-Deposit mode, floating AI trigger lock badge, security status tags) MUST use neutral monochrome styling (`text-muted-foreground bg-card border-border`).

## 2. Standardized `ProLockOverlay` Component
- All locked PRO features across all views (AI Ingestion, AI Chat Drawer, Projection Graph, Cycle Forecast Card, Settings Modal PRO controls, Phone Webhook Sync) MUST be masked cleanly using the standard `<ProLockOverlay />` component.
- On chart/graph overlays, wrap `ProLockOverlay` in an opaque/blurred `bg-background/95 backdrop-blur-md` backdrop so underlying data is completely non-interactive and hidden.

## 3. No Pseudo-Terminal Underscore Typography Invariant
- Ban pseudo-terminal uppercase underscore jargon in UI copy (e.g., `PRO_ACTIVE`, `CORE_FREE`, `PRO_LOCKED`, `HTTP_403_DENIED`, `SECURITY_GATEKEEPER`, `SUPER_USER`).
- Always use clean, professional natural English typography (e.g., `PRO Active`, `Core Free`, `PRO Locked`, `Access Forbidden`, `Security & Permissions`).

## 5. Proprietary AI Model Copy Invariant (Legal & SLA Protection)
- **No Third-Party Model Naming in Public Copy**: Avoid hardcoding third-party model names (e.g., `Gemini 2.5 Pro`, `GPT-4o`) in public feature bullets, PRO conversion cards, or user-facing footers.
- **Abstracted AI Capability Terminology**: Use clean proprietary terminology (e.g., `AI Neural Ingestion & Categorization`, `AI Processing Engine`, `AI Intelligence Node`). Third-party model names are strictly restricted to technical settings dropdown options (e.g. custom API key setup).

## 6. Dynamic Localized PRO Pricing Engine
- **Base Pricing Anchor**: Base PRO subscription price is anchored at **4.99 EUR** (`EUR: €4.99/mo`).
- **Clean Consumer Rounding**: All supported currency conversions are mapped to clean `.50` or `.00` consumer pricing via `getProPrice(currencyCode)` in `@/lib/format`:
  - `EUR`: **€4.99/mo**
  - `USD`: **$5.50/mo**
  - `GBP`: **£4.50/mo**
  - `BRL`: **R$29.50/mo**
  - `CAD`: **C$7.50/mo**
  - `AUD`: **A$8.50/mo**
  - `JPY`: **¥800/mo**
  - `CHF`: **CHF4.50/mo**
## 7. Core Base Minimalist Branding & High-Friction Churn Retention Flow
- **Core Base Naming & Uninviting Styling**: Non-PRO tier is strictly titled `LEGER_OS Core`. Its card in System Settings is styled with ultra-minimalist subtle styling (`bg-card/40 border-border/40 opacity-70`) so users are not incentivized to click or downgrade.
- **Dedicated Full-Screen Non-Draggable Slide-Up Screen (`CancelProModal.tsx`)**: Clicking "Cancel PRO Subscription" triggers a 100% full-screen slide-up sheet (`initial={{ y: "100%" }} animate={{ y: 0 }}`). It is strictly non-draggable to prevent accidental swipe dismissals.
- **Digestible Step-by-Step Sequence**: Presents clear, concise information step by step (Step 1: Benefits Risk $\rightarrow$ Step 2: One-Click Survey $\rightarrow$ Step 3: Retargeting Offer) without cluttering any single screen.
- **Multi-Step Psychological Churn Prevention Flow**:
  1. **Step 1 (Loss Aversion & Feature Breakdown)**: Displays explicit warning of lost capabilities (Android push sync, statement receipt parsing, recency-decay λ forecasts, conversational AI overrides) with a high-visibility Emerald CTA (`Keep My PRO Benefits`) and low-emphasis cancel link.
  2. **Step 2 (Exit Survey & Data Collection)**: Collects structured cancellation reasons (`too_expensive`, `not_using_enough`, `technical_issue`, `missing_features`, `other`) and optional text feedback.
  3. **Step 3 (Psychological Retargeting Offer / Farewell)**:
     - **First-time churner** (no prior `ai_journal.retention_discount_claimed_at`): Presents a **ONE-TIME exclusive 50% Retention Discount** (`€2.49/mo` / localized equivalent for 3 months) for all churn reasons. Contextual copy adjusts per reason — price/usage: emphasizes keeping features; technical/feature: emphasizes improvements in progress.
     - **Repeat churner** (already claimed discount): No discount offered. Shows a warm farewell (`We understand. You're always welcome back.`) with the 90-day PRO data retention breakdown, plus a strong `Actually, I'll stay on PRO` CTA.
  4. **Step 4 (Feedback Ingestion, State Transition & Data Retention)**: Stores survey feedback in `ai_journal.churn_survey`. On cancellation, writes `ai_journal.pro_data_retention_deadline` (90 days from cancellation date). On discount claim, writes `ai_journal.retention_discount_claimed_at` timestamp as the one-time gate.

## 8. Data Retention Policy (Post-Downgrade)
- **Transactions & categories**: Retained **permanently** on Core tier.
- **PRO-processed data** (AI insights, parsed statements, forecast snapshots, conversational overrides): Retained for **90 days** after downgrade. Deadline stored in `ai_journal.pro_data_retention_deadline`.
- **Full account deletion**: 30-day grace period, then full purge (separate flow in settings).
- Users are informed of the 90-day window during the cancellation flow (Step 3, both farewell and first-time variants).

## 9. Subpage UI & Typography Normalization Standard
- **Header Eyebrow**: `flex items-center gap-3 text-[9px] md:text-[10px] font-mono tracking-[0.2em] uppercase text-muted-foreground` with standard Lucide icon + uppercase title.
- **Page Title (`h1`)**: `<h1 className="text-4xl md:text-5xl font-bold tracking-tighter uppercase leading-none break-words">` using Geist Sans (`font-sans`).
- **Executive Metric Cards**: `<Tilt rotationFactor={6} className="p-5 md:p-6 space-y-3 bg-card/20 border border-border relative group overflow-hidden flex flex-col justify-between glow-card">` with `<span className="technical-label text-[9px] border-b border-dotted border-muted-foreground/30 w-fit z-10">`, monospaced values (`text-3xl md:text-5xl font-mono font-bold tracking-tighter z-10`).
- **Tab Controls**: `border border-border bg-card/20 text-xs font-mono` with active `bg-secondary text-foreground border-b-2 border-b-foreground` states.
- **Floating Add Button**: White rounded-xl square FAB (`fixed bottom-20 right-4 z-50 h-12 w-12 rounded-xl bg-white text-black font-extrabold shadow-2xl flex items-center justify-center hover:bg-gray-100 border border-white/20`) on mobile routes.
- **Pre-Flight Design Verification**: Before writing or refactoring any page view, check existing normalized views (`ExpensesView.tsx`) to guarantee 100% font family, text scale, border, and spacing coherence.

## 10. Native Draggable Bottom Drawer Standard
- All input, edit, and configuration overlays across the application (Add Position, Add Transaction Entry, Stripe Payments, AI Query Drawer) MUST use native bottom slide-up drawers instead of standard center dialog modals.
- **Drawer Requirements**:
  1. **Framer Motion slide-up animation**: `initial={{ y: "100%", opacity: 0 }} animate={{ y: 0, opacity: 1 }} exit={{ y: "100%", opacity: 0 }}`.
  2. **Top Drag Handle**: `w-12 h-1 bg-muted-foreground/30 rounded-full mx-auto my-2 cursor-grab active:cursor-grabbing`.
  3. **Draggable swipe-down dismiss gesture**: `drag="y" dragConstraints={{ top: 0, bottom: 0 }}` with `onDragEnd` triggering `onClose()` when swiped down >100px or velocity >500px/s.
  4. **Dark Background & Backdrop Blur**: `bg-[#09090b]` background with `backdrop-blur-md bg-background/80` backdrop overlay.

## 11. Metric Card Density & Anti-Void Invariant
- **Compact Padding**: All metric and executive cards on the dashboard and subpages MUST use compact `p-5 md:p-6 space-y-2.5 md:space-y-3` padding. Banned: bloated `p-6 md:p-8 space-y-4` which wastes 48px–64px per card and causes artificial height voids on mobile viewports.
- **Zero Card Stacking Clutter**: The dashboard financial summary uses a streamlined 3-Card Core (`LIQUIDITY POSITION`, `TOTAL INFLOW`, `TOTAL OUTFLOW`) rather than redundant 5-card stacks. Redundant subtraction cards or conflicting "consumed" percentage baselines are strictly banned.
- **Dynamic Half-Life Decay Pacing**: Pacing status (`OPTIMAL PACING` vs `HIGH BURN`) and half-life labels MUST dynamically compute from the user-configured recency decay parameter:
  $$\text{Half-Life Days} = \text{round}\left(\frac{\ln(2)}{\lambda}\right)$$
  Displaying `{halfLifeDays}D RECENCY DECAY` instead of hardcoded strings.

## 12. Macro Trajectory Telemetry Bar Standard
- **Inline Key Metrics**: The chart header statistics bar MUST display a unified, single-row 3-part telemetry strip:
  `NET CASH FLOW: +€XX.XX | DAILY BURN: €XX.XX/d | PROJECTED CLOSE: +€XX.XX`
- **Zero Decorative Slop**: Banned decorative green/red dot icons or emojis in the telemetry bar. All data points use clean natural English labels with color-reactive monospaced figures.

## 13. Symmetrical Action Buttons & FAB Menu Standard
- **Uniform Dimensions**: Floating Action Menu popup buttons (e.g. `INGEST STATEMENT` and `ADD TRANSACTION`) MUST share identical fixed widths (e.g. `w-60`), identical left/right padding, and `justify-between` alignment so outer borders align symmetrically.
- **Uniform Icon Containers**: Icon containers inside action menus MUST share the exact same styling (`w-9 h-9 bg-secondary border border-border flex items-center justify-center text-foreground group-hover:bg-foreground group-hover:text-background transition-colors shrink-0`), standard stroke width (`stroke-[2]`), and hover states.

## 14. Responsive Tablet Collapsible Sidebar Standard
- **Auto-Collapse on Tablet**: Side navigation automatically collapses to an icon rail (`w-16` / `64px`) on tablet viewports (768px - 1024px) to maximize screen area for charts and tables.
- **Manual Collapse Control**: Sidebar header features a `PanelLeftClose` / `PanelLeftOpen` toggle button.
- **Dynamic Content Padding**: `<main>` content container transitions padding dynamically (`isSidebarCollapsed ? "md:pl-16" : "md:pl-64"`) with smooth 300ms transition. User preference is persisted in `localStorage.getItem("leger_sidebar_collapsed")`.

## 15. React 19 Hydration & Server-Safe Initialization Standard
- **Null-Initialized Client State**: In multi-provider contexts (`SystemContext.tsx`), user profile and session states MUST initialize to `null` on server and client first pass, populating cached local storage values strictly inside a client `useEffect` to prevent React 19 hydration mismatch errors.
- **Script Tag Warning Prevention**: `<ThemeProvider>` must configure explicit `defaultTheme="dark"` and `enableSystem={false}` with `suppressHydrationWarning` on `<body>` to eliminate React 19 inline script injection warnings.
